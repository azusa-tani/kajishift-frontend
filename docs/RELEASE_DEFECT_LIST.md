# KAJISHIFT リリース判定用 不具合・保留事項一覧

## 1. 文書の目的

- 本書は、KAJISHIFTのリリース前テストで検出された不具合・保留事項を管理するための資料である。
- `docs/RELEASE_TEST_RESULTS.md` で NG または保留となった項目を、本書に転記して管理する。
- 不具合の重大度・優先度・対応状況・リリース可否への影響を明確にする。
- 最終的なリリース可否判断は `docs/RELEASE_CRITERIA.md` と合わせて行う。

## 2. 前提

- 対象は `kajishift-frontend` および `kajishift-backend`。
- テスト結果は `docs/RELEASE_TEST_RESULTS.md` を正とする。
- 不具合IDは `DEF-001` から連番で採番する。
- 保留・要確認事項は `PEND-001` から連番で採番する。
- 初期状態では、実際の不具合は未登録とし、テンプレートとして作成する。
- 実際にNGや保留が発生した場合に、本書へ追記する。

## 3. 不具合管理ルール

- `docs/RELEASE_TEST_RESULTS.md` で判定が `NG` になった項目は、原則として本書の「不具合一覧」に登録する。
- 判定が `保留` になった項目は、「保留・要確認事項一覧」に登録する。
- リリース必須「Yes」のテストケースで発生したNGは、原則としてリリース不可候補とする。
- 重大度「致命的」または「高」の不具合は、原則としてリリース前に修正完了が必要。
- 重大度「中」以下で回避策がある場合は、リリース判定会議で残課題として扱うことができる。
- 不具合を修正した場合は、再テスト結果を必ず記録する。
- 修正しないままリリースする場合は、リリース判定会議で承認を得る。
- 仕様不明・環境不足・テストデータ不足の場合は、不具合ではなく保留事項として管理する。

## 4. 重大度・優先度の定義

### 重大度

| 重大度 | 意味 | リリース可否への基本影響 |
|---|---|---|
| 致命的 | サービス全体停止、ログイン不可、主要業務全停止、重大な情報漏えい | 原則リリース不可 |
| 高 | 予約、決済、権限、管理機能など主要業務に影響 | 原則リリース前修正 |
| 中 | 一部機能に影響するが回避策がある | 判定会議で判断 |
| 低 | 表示崩れ、文言、軽微なUX問題 | リリース後対応可 |

### 優先度

| 優先度 | 意味 | 対応目安 |
|---|---|---|
| P1 | 最優先で対応 | リリース前必須 |
| P2 | 高優先で対応 | リリース前推奨 |
| P3 | 通常対応 | リリース後対応も可 |
| P4 | 低優先 | バックログ管理 |

## 5. ステータス定義

| ステータス | 意味 |
|---|---|
| 未対応 | 不具合を登録したが、まだ対応していない |
| 調査中 | 原因調査中 |
| 修正中 | 修正作業中 |
| 修正済み | 修正完了、再テスト待ち |
| 再テストOK | 再テストで問題なし |
| 再テストNG | 再テストで問題が残っている |
| 保留 | 仕様・環境・判断待ち |
| 対象外 | 今回リリース範囲外 |
| 既知の制限 | 修正せず制限事項として扱う |
| クローズ | 対応完了 |

## 6. リリース可否への影響判断

| 条件 | 扱い |
|---|---|
| 致命的な未解決不具合がある | リリース不可 |
| 重大度「高」の未解決不具合がある | 原則リリース不可 |
| リリース必須YesのテストケースでNGがある | 原則リリース不可 |
| 権限・認証・個人情報・決済に関する未解決不具合がある | 原則リリース不可 |
| 回避策のない予約・ワーカー・管理機能の不具合がある | 原則リリース不可 |
| 重大度「中」で回避策がある | 判定会議で判断 |
| 重大度「低」の軽微な不具合のみ | リリース後対応可 |
| 保留事項がリリース条件に関わる | 判定会議で判断 |
